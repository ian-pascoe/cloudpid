# How do existing MCP hosts surface MCP prompts and `completion/complete`?

Conventions: **[V]** verified in a primary source (cited), **[I]** inference (reasoned from sources, not stated by them), **[U]** the source is silent.

Sources are the hosts' own documentation and their source code, cited as permalinks to the commits read on the research date: `microsoft/vscode@41ac65b`, `zed-industries/zed@14b7b0e`, `google-gemini/gemini-cli@40fefe0`, `block/goose@090dedb`, `sst/opencode@cb1e58f` (the `packages/core` MCP client; `sst/opencode` is the same repository as `anomalyco/opencode`), `openai/codex@4c8f697`. Claude Code and Cursor are closed source, so for them only documentation is cited and everything the docs do not state is **[U]**. Per-host line numbers refer to those commits. Notation: "wire method" is the MCP method name; the spec calls autocompletion `completion/complete`.

## 2. Claude Code (documentation only)

- **Exposed and named [V].** "MCP servers can expose prompts that become available as commands in Claude Code." "Type `/` to see the commands available to you, including those from MCP servers. Claude Code lists each MCP prompt as `/servername:promptname (MCP)`. Typing `/mcp__servername__promptname` also runs it." [mcp docs › Use MCP prompts as commands](https://code.claude.com/docs/en/mcp.md#use-mcp-prompts-as-commands)
- **Sanitising [V].** "In the `/mcp__servername__promptname` form, Claude Code replaces any character in the server name outside `A-Z`, `a-z`, `0-9`, `_`, and `-` with `_`, and uses the prompt name as the server declares it." Same section.
- **Collisions.** The only collision rule documented is reserved: prompts from a server named `anthropic-skills` "don't appear" because the name is reserved for skills synced from claude.ai. [Same section](https://code.claude.com/docs/en/mcp.md#use-mcp-prompts-as-commands); [slash-commands](https://code.claude.com/docs/en/slash-commands.md) repeats it. The picker label contains the server name and the long form includes it, so two servers' same-named prompts differ by construction **[I]**. How a collision with a built-in or skill is resolved is **[U]**.
- **Arguments [V].** "Pass them space-separated after the command. Claude Code splits the arguments on whitespace, so each argument is a single token" (`/mcp__jira__create_issue login-bug high`); "Arguments are parsed based on the prompt's defined parameters". Quoting, `--name=value`, and required-argument errors are **[U]**.
- **Insertion [V/U].** "Prompt results are injected directly into the conversation". Whether `assistant` messages become assistant turns, and how images, audio, embedded resources and resource links are handled, is **[U]** in the docs. No "untrusted" marking is documented for prompt results; the general MCP warning is "Verify you trust each server before connecting it. Servers that fetch external content can expose you to prompt injection risk" ([mcp docs](https://code.claude.com/docs/en/mcp.md)).
- **`completion/complete`.** Not mentioned anywhere in the MCP page (searched for "completion") **[U]**.
- **Model access.** The docs describe prompts only as user commands **[U]** for any model-callable path.
- **`list_changed` [V].** "An MCP server can change the tools, prompts, or resources it offers while connected and send a `list_changed` notification." In an interactive terminal session Claude Code fetches the updated list; "In non-interactive mode with the `-p` flag and in the Agent SDK, Claude Code refreshes only the tool list on these notifications." If a refresh fails it keeps the previous lists. [mcp docs › Dynamic tool updates](https://code.claude.com/docs/en/mcp.md#dynamic-tool-updates)

## 3. VS Code (GitHub Copilot Chat)

All links: `microsoft/vscode@41ac65b056070e8fd5617580b82feb0b17632117`, under `src/vs/workbench/contrib/`.

- **Exposed and named [V].** Docs: "Prompts: use a server's prompt template by typing `/<server>.<prompt>` in chat." ([VS Code MCP docs › Use context and prompts from your server](https://code.visualstudio.com/docs/copilot/customization/mcp-servers)). Source: the slash-command completion provider builds the label `/mcp.${prompt.id}` for every prompt of every server ([chatInputCompletions.ts#L376](https://github.com/microsoft/vscode/blob/41ac65b056070e8fd5617580b82feb0b17632117/src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts#L376)); `prompt.id` is `mcpPromptReplaceSpecialChars(server.definition.label + '.' + name)` ([mcpServer.ts#L1279](https://github.com/microsoft/vscode/blob/41ac65b056070e8fd5617580b82feb0b17632117/src/vs/workbench/contrib/mcp/common/mcpServer.ts#L1279)) and the replacement is `s.replace(/[^a-z0-9_.-]/gi, '_')` ([mcpTypes.ts#L606](https://github.com/microsoft/vscode/blob/41ac65b056070e8fd5617580b82feb0b17632117/src/vs/workbench/contrib/mcp/common/mcpTypes.ts#L606)). The server label prefix is the collision guard; two servers with the same label would collide **[I]**. Completions are not offered when the widget has a locked agent (`widget.lockedAgentId`, [L370](https://github.com/microsoft/vscode/blob/41ac65b056070e8fd5617580b82feb0b17632117/src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts#L370)).
- **Arguments [V].** Picking the entry runs `StartParameterizedPromptAction`, which starts the server, opens `McpPromptArgumentPick` and awaits `createArgs()` ([L808](https://github.com/microsoft/vscode/blob/41ac65b056070e8fd5617580b82feb0b17632117/src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts#L808)). That is a quick-pick with one step per declared argument (`totalSteps = prompt.arguments.length`), with a Back button ([mcpPromptArgumentPick.ts](https://github.com/microsoft/vscode/blob/41ac65b056070e8fd5617580b82feb0b17632117/src/vs/workbench/contrib/mcp/browser/mcpPromptArgumentPick.ts)). Each step offers "Insert as text", "Run as Command" (terminal output becomes the value), server suggestions, the active file / selection, and file search ([L137](https://github.com/microsoft/vscode/blob/41ac65b056070e8fd5617580b82feb0b17632117/src/vs/workbench/contrib/mcp/browser/mcpPromptArgumentPick.ts#L137)). **Required:** accepting an empty value for a required argument sets the validation message "This argument is required" ([L182](https://github.com/microsoft/vscode/blob/41ac65b056070e8fd5617580b82feb0b17632117/src/vs/workbench/contrib/mcp/browser/mcpPromptArgumentPick.ts#L182)); optional ones may be left empty. Escape cancels and clears the typed command.
- **`completion/complete` for prompt arguments [V].** `McpPrompt.complete()` sends `ref: { type: 'ref/prompt', name }`, `argument: { name, value: prefix }` and `context: { arguments: alreadyResolved }` (previously entered values with non-empty text) ([mcpServer.ts#L1294](https://github.com/microsoft/vscode/blob/41ac65b056070e8fd5617580b82feb0b17632117/src/vs/workbench/contrib/mcp/common/mcpServer.ts#L1294)), through the `completion/complete` request ([mcpServerRequestHandler.ts#L544](https://github.com/microsoft/vscode/blob/41ac65b056070e8fd5617580b82feb0b17632117/src/vs/workbench/contrib/mcp/common/mcpServerRequestHandler.ts#L544)). Only `completion.values` is used.
- **Debounce / caching [V].** `SUGGEST_DEBOUNCE = 200` ms: each change of the quick-pick text cancels the previous request, waits 200 ms, then calls the completer; errors are swallowed into an empty list ([`_asyncCompletions`, L331](https://github.com/microsoft/vscode/blob/41ac65b056070e8fd5617580b82feb0b17632117/src/vs/workbench/contrib/mcp/browser/mcpPromptArgumentPick.ts#L331)). No cache for prompt-argument completions. The call is not gated on the server's `completions` capability in these files (the flag is only encoded into the stored capability bitmask, [mcpServer.ts#L1305](https://github.com/microsoft/vscode/blob/41ac65b056070e8fd5617580b82feb0b17632117/src/vs/workbench/contrib/mcp/common/mcpServer.ts#L1305)); a server without the capability would answer with an error, which is swallowed **[I]**.
- **`completion/complete` for resource template variables [V].** `McpResourceTemplate.complete()` sends `ref: { type: 'ref/resource', uri: uriTemplate }` with the already-resolved variables as `context.arguments` (array values joined with `/`) ([mcpServer.ts#L1541](https://github.com/microsoft/vscode/blob/41ac65b056070e8fd5617580b82feb0b17632117/src/vs/workbench/contrib/mcp/common/mcpServer.ts#L1541)). The "MCP Resources" quick access calls it per template variable and memoises the promise by input string in a `Map`, deleting the entry on failure ([mcpResourceQuickAccess.ts#L308](https://github.com/microsoft/vscode/blob/41ac65b056070e8fd5617580b82feb0b17632117/src/vs/workbench/contrib/mcp/browser/mcpResourceQuickAccess.ts#L308)). No debounce is visible there beyond the per-input cache.
- **Insertion [V].** The resolved `prompts/get` messages are *not* sent as a turn. They are converted into the chat input text plus attachments, and the user then sends it ([L877-L908](https://github.com/microsoft/vscode/blob/41ac65b056070e8fd5617580b82feb0b17632117/src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts#L877)):
  - **Roles:** all `text` blocks are concatenated into one string separated by blank lines; if the messages have more than one role, each is prefixed with `--USER` / `--ASSISTANT` ([L877-L886](https://github.com/microsoft/vscode/blob/41ac65b056070e8fd5617580b82feb0b17632117/src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts#L877)). So `assistant` messages are flattened into the user message, not real assistant turns.
  - **Images and audio:** `image`/`audio` blocks go to `attachBlob` with no URI. A MIME type with an attachable image extension becomes an `image` attachment (resized); anything else, including every `audio` block, matches no branch and is dropped ([L826](https://github.com/microsoft/vscode/blob/41ac65b056070e8fd5617580b82feb0b17632117/src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts#L826), [L898](https://github.com/microsoft/vscode/blob/41ac65b056070e8fd5617580b82feb0b17632117/src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts#L898)) **[I]** from the `attachBlob` branches (audio MIME types are not image extensions).
  - **Embedded resources:** text → a `file` attachment if the URI resolves in the file service (raw or as an `mcp-resource` URI), else a generic "Prompt Resource" attachment with the text; binary → image attachment if the MIME is an image, else a file attachment if the URI resolves, else dropped.
  - **Resource links:** the `switch` has no `resource_link` case, so they are ignored **[V]** (no match for `resource_link` in the file).
  - **Untrusted marking:** none visible in this path **[V]** (nothing in the file marks the content as untrusted); content lands in an editable input the user reviews before sending **[I]**.
- **Model access.** No tool wrapping `prompts/get` found in `contrib/mcp` (searched for prompt/`getPrompt` usage; the only consumers are the slash-command completion and the argument picker) **[V]** for the searched tree.
- **`list_changed` [V].** `notifications/prompts/list_changed` fires `onDidChangePromptList` ([mcpServerRequestHandler.ts#L377](https://github.com/microsoft/vscode/blob/41ac65b056070e8fd5617580b82feb0b17632117/src/vs/workbench/contrib/mcp/common/mcpServerRequestHandler.ts#L377)), which logs "Prompts list changed, refreshing prompts..." and re-lists ([mcpServer.ts#L1243](https://github.com/microsoft/vscode/blob/41ac65b056070e8fd5617580b82feb0b17632117/src/vs/workbench/contrib/mcp/common/mcpServer.ts#L1243)).

## 4. Zed

Links: `zed-industries/zed@14b7b0ef3764d62a85070c8b5ccea105a2ad3235`.

- **Exposed [V].** Docs: "Zed currently supports MCP's Tools and Prompts features." and "Zed also handles the `notifications/tools/list_changed` notification" ([Zed MCP docs](https://zed.dev/docs/ai/mcp)).
- **Naming and collisions [V].** The command is the bare prompt name; if the name is shared by more than one MCP prompt or collides with the built-in `/compact`, it is forced to `<server_id>.<prompt>` ([agent.rs#L1738-L1752](https://github.com/zed-industries/zed/blob/14b7b0ef3764d62a85070c8b5ccea105a2ad3235/crates/agent/src/agent.rs#L1738); [`ambiguous_mcp_prompt_names`, L194](https://github.com/zed-industries/zed/blob/14b7b0ef3764d62a85070c8b5ccea105a2ad3235/crates/agent/src/agent.rs#L194): "A built-in always wins an unqualified invocation"). On dispatch, MCP prompts are matched before skills: "if a user has both an MCP prompt and a skill with the same name, the MCP prompt wins" ([L307-L317](https://github.com/zed-industries/zed/blob/14b7b0ef3764d62a85070c8b5ccea105a2ad3235/crates/agent/src/agent.rs#L307)).
- **Arguments [V].** A prompt with exactly one argument is advertised with a text hint `<argname>`; prompts with more than one argument are skipped entirely: "skip >1 argument commands since we don't support them yet" ([L1755-L1771](https://github.com/zed-industries/zed/blob/14b7b0ef3764d62a85070c8b5ccea105a2ad3235/crates/agent/src/agent.rs#L1769)). On dispatch, the text after the command (if non-empty) is assigned to the *first* declared argument; if empty, no arguments are sent, so required-argument handling is whatever the server does with a missing one (no client-side check) ([L317-L335](https://github.com/zed-industries/zed/blob/14b7b0ef3764d62a85070c8b5ccea105a2ad3235/crates/agent/src/agent.rs#L317)).
- **`completion/complete`: not used [V].** `completion/complete` is only defined as a request type with its params struct ([context_server/src/types.rs#L74](https://github.com/zed-industries/zed/blob/14b7b0ef3764d62a85070c8b5ccea105a2ad3235/crates/context_server/src/types.rs#L74)); no other crate in the tree references `CompletionComplete`. Zed does not request completions for prompt arguments or resource template variables.
- **Insertion [V].** `send_mcp_prompt` calls `prompts/get` ([`get_prompt`, context_server_registry.rs#L511](https://github.com/zed-industries/zed/blob/14b7b0ef3764d62a85070c8b5ccea105a2ad3235/crates/agent/src/tools/context_server_registry.rs#L511)) and then walks the messages: `Role::User` → a user message in the thread and the UI; **`Role::Assistant` → a real assistant block in the thread** (`push_acp_agent_block`) and in the UI ([agent.rs#L2205](https://github.com/zed-industries/zed/blob/14b7b0ef3764d62a85070c8b5ccea105a2ad3235/crates/agent/src/agent.rs#L2205)). If the last message was not from the user, the thread is *resumed* instead of sending a new user message ([L2230](https://github.com/zed-industries/zed/blob/14b7b0ef3764d62a85070c8b5ccea105a2ad3235/crates/agent/src/agent.rs#L2230)), and the prompt turn runs immediately (no review step).
- **Content types [V].** [`mcp_message_content_to_acp_content_block`, L10269](https://github.com/zed-industries/zed/blob/14b7b0ef3764d62a85070c8b5ccea105a2ad3235/crates/agent/src/agent.rs#L10269): text, image and audio map to the same ACP block types with annotations preserved; an embedded `resource` is **converted to an ACP `ResourceLink`** carrying only the URI (and MIME type); the embedded text/blob body is not forwarded ([L10304](https://github.com/zed-industries/zed/blob/14b7b0ef3764d62a85070c8b5ccea105a2ad3235/crates/agent/src/agent.rs#L10304)). The context-server `MessageContent` enum has only `text`, `image`, `audio` and `resource` variants ([types.rs#L361](https://github.com/zed-industries/zed/blob/14b7b0ef3764d62a85070c8b5ccea105a2ad3235/crates/context_server/src/types.rs#L361)), so a `resource_link` block in a `prompts/get` result has no variant to deserialise into **[I]**; what Zed does on that parse failure is **[U]**. Untrusted marking: none visible **[V]** in that function.
- **Model access.** No tool for prompts: the registry registers tools from `tools/list` only; prompts are held for slash commands (`reload_prompts_for_server`, [L210](https://github.com/zed-industries/zed/blob/14b7b0ef3764d62a85070c8b5ccea105a2ad3235/crates/agent/src/tools/context_server_registry.rs#L210)) **[V]**.
- **`list_changed`: tools only [V].** The registry subscribes to `notifications/tools/list_changed` only ([context_server_registry.rs#L143](https://github.com/zed-industries/zed/blob/14b7b0ef3764d62a85070c8b5ccea105a2ad3235/crates/agent/src/tools/context_server_registry.rs#L143), the only `on_notification` call in the agent crate). The `PromptsListChanged` notification type exists ([types.rs#L125](https://github.com/zed-industries/zed/blob/14b7b0ef3764d62a85070c8b5ccea105a2ad3235/crates/context_server/src/types.rs#L125)) but has no subscriber. Prompts are reloaded when a server transitions to `Running`.

## 5. Gemini CLI

Links: `google-gemini/gemini-cli@40fefe0ae0fc00b371c88828997859d68576ffe9`.

- **Exposed [V].** Docs section "MCP prompts as slash commands" ([docs/tools/mcp-server.md#L1065](https://github.com/google-gemini/gemini-cli/blob/40fefe0ae0fc00b371c88828997859d68576ffe9/docs/tools/mcp-server.md#L1065)); `McpPromptLoader` turns each prompt into a `SlashCommand` of kind `MCP_PROMPT` ([McpPromptLoader.ts](https://github.com/google-gemini/gemini-cli/blob/40fefe0ae0fc00b371c88828997859d68576ffe9/packages/cli/src/services/McpPromptLoader.ts#L45)).
- **Naming and collisions [V].** The name is the prompt name with whitespace runs replaced by `-`: no server prefix ([L45](https://github.com/google-gemini/gemini-cli/blob/40fefe0ae0fc00b371c88828997859d68576ffe9/packages/cli/src/services/McpPromptLoader.ts#L45)). Collisions: built-ins always keep the name; a colliding MCP prompt is renamed `<serverName>.<name>` (separator `.` for MCP, `:` only for skills/extension files), and if two non-built-ins collide *both* are renamed, with a numeric suffix as a last resort ([SlashCommandResolver.ts#L175](https://github.com/google-gemini/gemini-cli/blob/40fefe0ae0fc00b371c88828997859d68576ffe9/packages/cli/src/services/SlashCommandResolver.ts#L175)). Separately, within the core `PromptRegistry`, a duplicate prompt name across servers is stored as `<serverName>_<name>` ([prompt-registry.ts#L19](https://github.com/google-gemini/gemini-cli/blob/40fefe0ae0fc00b371c88828997859d68576ffe9/packages/core/src/prompts/prompt-registry.ts#L19)), so the CLI-level prefix applies only if the names still collide after that.
- **Arguments [V].** Docs: `/poem-writer --title="Gemini CLI" --mood="reverent"` or positionally `/poem-writer "Gemini CLI" reverent` ([docs L1122](https://github.com/google-gemini/gemini-cli/blob/40fefe0ae0fc00b371c88828997859d68576ffe9/docs/tools/mcp-server.md#L1122)). `parseArgs` ([L231-L305](https://github.com/google-gemini/gemini-cli/blob/40fefe0ae0fc00b371c88828997859d68576ffe9/packages/cli/src/services/McpPromptLoader.ts#L231)): named `--key=value` (quoted or not) first; remaining text is positional; **if exactly one required argument is unfilled, all remaining text is joined into it without quotes**; otherwise positionals fill unfilled required args in order, and missing ones produce the error `Missing required argument(s): --a, --b` ([L300](https://github.com/google-gemini/gemini-cli/blob/40fefe0ae0fc00b371c88828997859d68576ffe9/packages/cli/src/services/McpPromptLoader.ts#L300)). Optional arguments can only be given by name. A `help` sub-command prints each argument's description and `required: yes/no`. Prompts without arguments are `autoExecute` ([L51](https://github.com/google-gemini/gemini-cli/blob/40fefe0ae0fc00b371c88828997859d68576ffe9/packages/cli/src/services/McpPromptLoader.ts#L51)). Values are stringified before `prompts/get` ([`invokeMcpPrompt`, mcp-client.ts#L1613](https://github.com/google-gemini/gemini-cli/blob/40fefe0ae0fc00b371c88828997859d68576ffe9/packages/core/src/tools/mcp-client.ts#L1613)).
- **`completion/complete`: not used [V].** The command's `completion` handler ([L152](https://github.com/google-gemini/gemini-cli/blob/40fefe0ae0fc00b371c88828997859d68576ffe9/packages/cli/src/services/McpPromptLoader.ts#L152)) is purely local: it suggests the not-yet-used `--argname="` flag names from the prompt's declared arguments. `mcp-client.ts` never calls `client.complete`. Values and resource-template variables get no server-side completion.
- **Insertion [V].** The action takes **only `result.messages[0].content`**; if its `type` is not `text` it errors with "Received an empty or invalid prompt response from the server."; otherwise it returns `{ type: 'submit_prompt', content: JSON.stringify(text) }` ([L130-L143](https://github.com/google-gemini/gemini-cli/blob/40fefe0ae0fc00b371c88828997859d68576ffe9/packages/cli/src/services/McpPromptLoader.ts#L130)). So role is ignored (an `assistant` first message is still submitted as the user's prompt), later messages are dropped, and images, audio, resources and resource links are unsupported (they cause the error when first, and are silently dropped otherwise). The `JSON.stringify` means the submitted text is the JSON-quoted string; whether the submit path unquotes it is **[U]** (not traced). Untrusted marking: none **[V]**. The docs say only "The CLI then sends this prompt to the model for execution" ([docs L1137](https://github.com/google-gemini/gemini-cli/blob/40fefe0ae0fc00b371c88828997859d68576ffe9/docs/tools/mcp-server.md#L1122)).
- **Model access.** No tool found; prompts are held in `PromptRegistry` for the slash-command loader and only `invoke` closures call `prompts/get` **[V]** (searched `packages/core` and `packages/cli`).
- **`list_changed` [V].** A `PromptListChangedNotificationSchema` handler calls `refreshPrompts()` even if the server did not declare `prompts.listChanged` ("Listening anyway for robustness") ([mcp-client.ts#L464-L469](https://github.com/google-gemini/gemini-cli/blob/40fefe0ae0fc00b371c88828997859d68576ffe9/packages/core/src/tools/mcp-client.ts#L464)); refreshes are serialised with a pending flag, and if the list looks unchanged it retries once after 500 ms ([L541](https://github.com/google-gemini/gemini-cli/blob/40fefe0ae0fc00b371c88828997859d68576ffe9/packages/core/src/tools/mcp-client.ts#L541)). A server without a `prompts` capability gets no `prompts/list` ([L1522](https://github.com/google-gemini/gemini-cli/blob/40fefe0ae0fc00b371c88828997859d68576ffe9/packages/core/src/tools/mcp-client.ts#L1526)).

## 6. Goose

Links: `block/goose@090dedb7625c8aadb9bb05d68028fd00f36b429e` (CLI session code in `crates/goose-cli`).

- **Exposed and named [V].** Prompts are not slash-per-prompt; there are two fixed commands: `/prompts [--extension <name>]` and `/prompt <n> [--info] [key=value...]` ([CLI commands docs](https://goose-docs.ai/docs/guides/goose-cli-commands); [execute_commands.rs#L23](https://github.com/block/goose/blob/090dedb7625c8aadb9bb05d68028fd00f36b429e/crates/goose/src/agents/execute_commands.rs#L23)). Collisions: `get_prompt` finds the **first** extension whose list contains the name (`find(|(_, prompts)| …)`, [session/mod.rs#L561](https://github.com/block/goose/blob/090dedb7625c8aadb9bb05d68028fd00f36b429e/crates/goose-cli/src/session/mod.rs#L561)); same-named prompts in two extensions are not disambiguated **[V]**, and which one wins depends on the map iteration order **[I]**.
- **Arguments [V].** [`parse_prompt_command`](https://github.com/block/goose/blob/090dedb7625c8aadb9bb05d68028fd00f36b429e/crates/goose-cli/src/session/input.rs#L373): shell-style `shlex` split; first token is the name; each later token containing `=` is split once into `key=value` ([L401](https://github.com/block/goose/blob/090dedb7625c8aadb9bb05d68028fd00f36b429e/crates/goose-cli/src/session/input.rs#L401)). No positional form, and no client-side required check (the server answers). `--info` prints name, description, arguments.
- **`completion/complete`: not used [V].** Tab completion is local: names come from a `CompletionCache` filled from `prompts/list`, and argument keys from the cached prompt info (`key=` for declared, unused arguments) ([completion.rs#L30](https://github.com/block/goose/blob/090dedb7625c8aadb9bb05d68028fd00f36b429e/crates/goose-cli/src/session/completion.rs#L30), [L275](https://github.com/block/goose/blob/090dedb7625c8aadb9bb05d68028fd00f36b429e/crates/goose-cli/src/session/completion.rs#L275), cache rebuilt at [mod.rs#L1871](https://github.com/block/goose/blob/090dedb7625c8aadb9bb05d68028fd00f36b429e/crates/goose-cli/src/session/mod.rs#L1871)). No value completion.
- **Insertion [V].** [`handle_prompt_command`](https://github.com/block/goose/blob/090dedb7625c8aadb9bb05d68028fd00f36b429e/crates/goose-cli/src/session/mod.rs#L2011) converts each `PromptMessage` into a conversation `Message` with the *same role* (`Role::Assistant` → `Message::assistant()`, [message.rs#L739](https://github.com/block/goose/blob/090dedb7625c8aadb9bb05d68028fd00f36b429e/crates/goose-provider-types/src/conversation/message.rs#L739)). It requires strict alternation starting with user ("ensure we get a User - Assistant - User type pattern", [L2035](https://github.com/block/goose/blob/090dedb7625c8aadb9bb05d68028fd00f36b429e/crates/goose-cli/src/session/mod.rs#L2035)); any mismatch prints an error and discards everything added. Valid history is persisted and the agent loop is started immediately. Content: `text` is kept after `sanitize_unicode_tags` (strips invisible Unicode tag characters, a prompt-injection mitigation) ([message.rs#L750](https://github.com/block/goose/blob/090dedb7625c8aadb9bb05d68028fd00f36b429e/crates/goose-provider-types/src/conversation/message.rs#L750)); `image` kept as an image; **resource link → the literal text `[Resource link]`**; embedded `resource` → its extracted text; **audio → `[Audio content: not supported]`**; anything else → `[Unsupported content]`. No "untrusted" label **[V]** beyond the Unicode-tag sanitising.
- **Model access.** The agent's tool surface is built from extension tools; the prompt calls are made only from the CLI session and the ACP server (`custom_dispatch.rs`, which exposes `list_prompts`/`get_prompt` to ACP clients such as editors, not to the model) **[V]** for the searched crates (`goose`, `goose-cli`, `goose-server`).
- **`list_changed`.** The MCP client handler overrides only `on_progress`, `on_tool_list_changed` and `on_logging_message` ([mcp_client.rs#L358](https://github.com/block/goose/blob/090dedb7625c8aadb9bb05d68028fd00f36b429e/crates/goose/src/agents/mcp_client.rs#L358)); there is no prompt handler, so `prompts/list_changed` is not acted on **[I]** (the default of the SDK trait is a no-op; the CLI cache is rebuilt from `list_prompts` at session start / after extension changes).

## 7. OpenCode

Links: `sst/opencode@cb1e58fe448237ce7cbd906764356e350a102566` (`packages/core`; the older `packages/opencode` tree no longer exists at this commit).

- **Exposed and named [V].** [`plugin/command.ts#L55-L57`](https://github.com/sst/opencode/blob/cb1e58fe448237ce7cbd906764356e350a102566/packages/core/src/plugin/command.ts#L55) registers one command per MCP prompt named `${sanitize(server)}:${sanitize(prompt)}` where `sanitize` replaces `[^a-zA-Z0-9_-]` with `_` ([L104](https://github.com/sst/opencode/blob/cb1e58fe448237ce7cbd906764356e350a102566/packages/core/src/plugin/command.ts#L104)). - **Arguments [V].** Purely positional: `parseArguments` splits on whitespace honouring `"…"` and `'…'` ([L92](https://github.com/sst/opencode/blob/cb1e58fe448237ce7cbd906764356e350a102566/packages/core/src/plugin/command.ts#L92), regex at L112) and maps token *i* to the *i*-th declared argument; missing tokens become `""` ([L61-L68](https://github.com/sst/opencode/blob/cb1e58fe448237ce7cbd906764356e350a102566/packages/core/src/plugin/command.ts#L61)). There is no required-argument check, no `--name=value`, and no per-argument form.
- **`completion/complete`: not used [V].** The MCP `Connection` type has no complete call and a search of `packages/core/src/mcp` finds none (the only "complete" hits are elicitation). Client capabilities declared are `elicitation` and `roots` only ([client.ts#L213](https://github.com/sst/opencode/blob/cb1e58fe448237ce7cbd906764356e350a102566/packages/core/src/mcp/client.ts#L213)).
- **Insertion [V].** After `prompts/get` ([client.ts#L422](https://github.com/sst/opencode/blob/cb1e58fe448237ce7cbd906764356e350a102566/packages/core/src/mcp/client.ts#L422)) all messages are mapped through `promptMessageText`, joined with `\n`, trimmed, and submitted as **one user prompt** ([L73-L77](https://github.com/sst/opencode/blob/cb1e58fe448237ce7cbd906764356e350a102566/packages/core/src/plugin/command.ts#L73)). Roles are ignored (assistant text becomes user text). `promptMessageText` returns text only for `type: "text"` and `""` for everything else, so **images, audio, embedded resources and resource links are silently dropped** ([L96](https://github.com/sst/opencode/blob/cb1e58fe448237ce7cbd906764356e350a102566/packages/core/src/plugin/command.ts#L96)). No untrusted marking **[V]**.
- **Model access.** No tool calls `prompts/get`; the only callers of `mcp.prompt(...)` are the slash-command plugin **[V]** (searched `packages/`, excluding generated clients).
- **`list_changed` [V].** The SDK client is constructed with `listChanged.prompts` (`autoRefresh: false`, `debounceMs: 0`) ([client.ts#L179](https://github.com/sst/opencode/blob/cb1e58fe448237ce7cbd906764356e350a102566/packages/core/src/mcp/client.ts#L179)); the callback refreshes prompts ([index.ts#L447](https://github.com/sst/opencode/blob/cb1e58fe448237ce7cbd906764356e350a102566/packages/core/src/mcp/index.ts#L447)), publishes `mcp.prompts.changed` ([L25](https://github.com/sst/opencode/blob/cb1e58fe448237ce7cbd906764356e350a102566/packages/core/src/mcp/index.ts#L25)) and the command plugin reloads its command list ([command.ts#L18](https://github.com/sst/opencode/blob/cb1e58fe448237ce7cbd906764356e350a102566/packages/core/src/plugin/command.ts#L18)). On a 2026-07-28 connection the client comment says the SDK opens `subscriptions/listen` itself.

## 10. Patterns across hosts

- **Prompts are a user-invoked surface everywhere they exist; none of the six source-readable hosts gives the model a prompt-fetch tool [V]** (VS Code, Zed, Gemini CLI, Goose, OpenCode, Codex: searched; Claude Code and Cursor: **[U]**).
- **Naming** splits three ways: server-qualified always (`/mcp.server.prompt` VS Code; `/server:prompt` OpenCode; `/mcp__server__prompt` Claude Code's long form), bare with collision-only qualification (`/prompt` → `/server.prompt`: Zed, Gemini CLI), and a generic command with the name as argument (`/prompt <name>`: Goose).
- **`completion/complete` is used by exactly one host, VS Code** (prompt arguments and resource template variables); Zed has the type defined but unused; Gemini CLI, Goose, OpenCode and Codex do no server-side completion; Claude Code and Cursor are **[U]**. VS Code is also the only host with a per-argument form and required-argument UI.
- **Role handling:** real assistant turns in Zed and Goose (Goose enforces alternation); flattened into user text in VS Code (with `--ASSISTANT` labels), OpenCode (no labels) and Gemini CLI (first message only).
- **Media:** VS Code attaches images and resources; Zed forwards image/audio and turns embedded resources into links; Goose keeps images and degrades links/audio to placeholder text; Gemini CLI and OpenCode are text-only.
- **No host in the source-readable set marks prompt content as untrusted** beyond Goose's Unicode-tag stripping and VS Code's put-it-in-the-editable-input-first flow **[V]/[I]**.
- **`prompts/list_changed`:** handled by Claude Code, VS Code, Gemini CLI, OpenCode; not handled by Zed (tools only) or Goose (tools only); logged by Codex.
