# The Container's image carries common Toolchains, and Toolchains are reinstalled from a synced lockfile

The Container image holds Ubuntu LTS (`ubuntu:26.04`) with the command-line tools a developer expects from apt (see the second revision below), `fuse3`, `ca-certificates`, `build-essential`, `computerd`, and `mise`, with mise's installs of one version each of git (`conda:git`), `gh`, Node (the current LTS), pnpm, Python, and uv. Every program a project uses is still a mise Toolchain declared in `mise.toml` and `mise.lock` inside the Workspace, so it follows the project: the image's installs are only there to be found. The image puts them in mise's system directory (`mise install --system`, `/usr/local/share/mise/installs`), which mise searches for a version a config asks for before it downloads one, and the base `mise.toml` a Workspace gets when it has none names exactly those versions, with the lockfile the image made for it, so a new Workspace downloads nothing. A Workspace that asks for other versions gets them as before: mise installs them on the Container's own disk, in its default directories, and `node_modules`, `.venv`, `target/`, and caches are on computer's `ignore` list. They stay on container-local disk, outside the synced SQLite filesystem. Before the first command of each Container start, the Workspace DO runs `mise install`, which does nothing if the tools are present, and disk snapshots taken after installs and idle stops make most restarts skip the download. A bootstrap that installed nothing (a Workspace using only the image's versions) takes no snapshot, so its first command does not wait for one; the idle stop's snapshot covers it.

The image first held no Toolchains at all (this ADR rejected a fat image because it "pins every project to one image's versions and grows without bound"). Deployed, a cold start spent about 15 s downloading Node and Python and 6 s on git and gh, and native npm and pip builds failed for lack of a compiler. The revision keeps versions with the project, which was the objection, and bounds the growth: the image carries one version of each of a short list, chosen because nearly every Workspace uses them (git and gh for every clone, Node and Python with their package managers for most projects), and a C toolchain because native packages of both need one. A Toolchain not on the list is never added to the image; a version on it moves when the image is refreshed, and a Workspace keeps the version its `mise.toml` names, downloading it if the image has moved on. The image grew from 134 MB to 467 MB compressed (369 MB to 1.3 GB on disk; measured 2026-10-22, see docs/spec.md → _Known risks and spikes_).

The Toolchains were first planned under `/workspace/.mise` on the `ignore` list. Deployed, computerd 0.5.1's FUSE fails `listxattr` with `ENOENT` on ignored paths, which broke Python's `shutil.copystat` (`python -m venv` could not copy ensurepip's wheels from its own install), so they stay off the mount: installs and `/tmp` then share one filesystem, which also keeps them clear of the `EXDEV` boundary. The image must be glibc-based because computerd is a glibc Node SEA.

A second revision moved the image from `debian:stable-slim` to Ubuntu LTS, with the everyday command-line tools from apt: `curl`, `wget`, `jq`, `ripgrep`, `unzip`, `procps`, `psmisc`, `less`, `openssh-client`, `sudo`, `sqlite3`, `build-essential`, `pkg-config` and the common `-dev` libraries. The slim image lacked them (agents reached for `curl`, `jq`, `free` and `pkill` and found nothing). Once custom images were dropped (ADR-0016), Setup and Start Scripts became the only way to shape a Workspace, so they build on this image and use apt for what is not a mise Toolchain. Ubuntu LTS is what Claude Code's and Codex's cloud environments run, so commands and install instructions an agent knows work as written. The split with mise stays: a program whose version a project cares about (Node, Python, pnpm, git, gh) is a mise Toolchain, and apt carries the tools whose version nobody pins. The image grows by the apt tools; under ADR-0016 a Workspace starts from its Environment's Build rather than from the image, so only a Build pays for the larger image.

A third revision moved the image from Ubuntu 24.04 to 26.04 LTS. computerd 0.8.0 (the version `@cloudflare/computer` 0.8.0 speaks to) links libfuse 3.17 or newer and exits at start without it (`computerd needs libfuse 3.17 or newer`), and 24.04 carries 3.14; 26.04 carries 3.18. libfuse 2 (`libfuse2t64`) went with it: computerd no longer links it. The newer libfuse is also what FUSE passthrough and native roots for the Container-only paths need, which also need Linux 6.9 or newer on the host.

## Considered Options

- **Persist Toolchain binaries in the synced Workspace.** computerd keeps the synced tree in container memory and re-pushes all of it after every container restart. Node alone is 213 MB in 4,750 files. That costs cold-start time and RAM in proportion to its size, and eats into the Durable Object's 10 GB SQLite cap. FUSE is also roughly 2× slower than ext4 for package installs.
- **A minimal image with no Toolchains.** The first form of this decision: smallest, but every cold start of a new Workspace downloads git, gh, and whatever runtime it uses, and native builds fail.
- **A fat image whose languages are the Toolchains.** Simpler, but it pins every project to one image's versions and grows without bound.
- **Preinstalling into mise's default data directory under `/root`** instead of its system directory. It works the same for lookups, but mixes the image's installs with the Workspace's own, where `mise prune` or `mise uninstall` can remove them; the system directory keeps them apart and `mise ls` labels them `(system)`.
- **The image's versions in mise's system config (`/etc/mise/config.toml`)** instead of the base `mise.toml`. Every Workspace would then get them without declaring them, so a project would depend on what the image happens to carry; the base `mise.toml` declares them in the Workspace, where they stay when the image moves on.
- **Fuzzy versions in the base `mise.toml`** (`node = "24"`). `mise lock` resolves a prefix to the newest release, which the image soon does not have, and then downloads it; the base file names exact versions.
