# The Session socket carries Schema messages, not alchemy's WebSocket RPC

Clients reach a Session over a hibernatable WebSocket to the Session DO that carries the message shapes of Cloudflare's `agents` pi example (`submit`, `abort`, `watch`/`unwatch`; `hello`, `events`, `result`, `error`), written as Effect `Schema` in `packages/protocol`. alchemy's `RpcDurableObject` WebSocket transport (2.0.0-beta.83) was the first choice, and a workerd test showed that it does not survive hibernation for the one call that matters, `watch`. An idle connection survives: after `evictDurableObject` a new instance answered the next unary call on the same socket. An open stream does not: the transport keeps the object alive with `waitUntil` until every request on the socket ends, so workerd refused to evict it ("it still has active references"). It also turns off the runtime's ping auto-response while a request is open, so every client ping wakes the object. A watched Session would therefore never hibernate, and an eviction (a deploy, a reset) closes the socket with 1012, leaving the client to reconnect and watch again. Our socket instead keeps each watch in memory and names the watched conversations in the socket's attachment. The runtime answers `ping` with `pong` without waking the object, a hibernated Session sleeps with its sockets open, and a woken instance restarts every watch with a fresh snapshot on the same socket. The Registry's list and create operations hold no stream, so they stay Effect RPC (`RegistryRpcs`), over HTTP from the main Worker.

## Considered Options

- **alchemy `RpcDurableObject` with clients that re-watch on close.** It meets "reconnect and get a fresh snapshot", but the Session stays in memory for as long as a client watches it.
- **Our own hibernation-aware Effect RPC server transport** that records open `watch` requests in the attachment and replays them on wake. It keeps one typed RPC client for everything, but means owning a second copy of alchemy's transport and Effect RPC's envelope rules. The example's shapes are also what the web reducer ported from the same example consumes.
