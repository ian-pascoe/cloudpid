# What a test is for

A test earns its place by catching a regression no other test catches. Each one is paid for in CI time, in review, and in every refactor that has to move it. So test each rule once, where it lives, and test the wiring above it lightly. How to run tests and the workerd specifics are in [`workers.md`](workers.md) → _workerd tests_.

## Rules

1. **The owner tests the rule.** Test a rule (a limit, a refusal, a mapping, a retry cap, a rate limit) in full in the module that owns it. Each entry point above it gets at most one pass-through test, which proves the wiring: an RPC handler, a socket message, a tool, a component. A shared mechanism is tested once, at its helper, and each tool or kind that uses it gets one pass-through. Examples: output bounds in `outputs.test.ts`; the socket's rate limits in `socket-requests.test.ts`; a server-initiated MCP request's wait, timeout and withdrawal in `packages/mcp`; Decline, no-op and Secret-in-reason in `approval-tools.test.ts`.
2. **Assert what the code computes.** A test of a constant, a default object, a table, a schema decoding a plain struct, or a JSON round trip passes by construction. Keep only invariants the code does not guarantee itself (for example, the default model is in `SUPPORTED_MODELS`), custom transforms, and one test per forward-compatibility mechanism ("an unknown value reads as `unknown`"; "a hello without the field still reads").
3. **Assert codes and structure, not prose.** Check the error code, kind, status, tool name or element. The wording of tool descriptions, prompts, notices, UI copy and error sentences is free to change. When a sentence is itself the contract, say why in the test.
4. **One row per branch.** An `it.each` table has one row for each branch the code takes, not one per spelling. Security parsers (routes, hosts, CSP sources, SSRF addresses) keep one row per rejection mechanism.
5. **Against a fake, test what the code under test does.** A test that reads back what a fake was seeded with tests the fake. Above a fake Registry or host, test validation before the call, upkeep after it, ordering, and error mapping.
6. **A workerd test covers what needs workerd:** Durable Object storage, alarms, eviction, a replaced instance, real git through the Workspace's file provider, and the binding's wiring. Scenarios its node twin already runs stay in the node test.
7. **A shim's test goes with the shim.** A test of a rename or migration shim, or a legacy redirect, is deleted in the change that deletes the shim. Shipped migrations are held by the manifest check (`scripts/check-migration-manifests.sh`).
8. **Run it instead of reading it.** Test a script, Dockerfile or config by running it, or leave it to the CI job that uses it. A test reads source text only to hold two copies of one value in lockstep (`apps/web/src/sandbox-frame/style-values.test.ts`).
9. **Spend CI time on coverage.** A test that spawns a build or a tool (vite, oxlint, rolldown) carries one positive and one negative case per rule. Time is checked by counting work, not with the wall clock. A measurement or a check that needs the network or a paid API runs on demand behind an environment flag that its doc names (`CHANGES_BENCH=1`; `MODEL_PROXY_API_KEY` in [`infra.md`](infra.md)).
