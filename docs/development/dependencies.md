# Patched and pinned dependencies

Some dependencies carry a patch (`patches/`) or an exact pin. When upgrading one, `pnpm install` fails on a stale patch: check whether upstream fixed the problem, drop the patch if so, else port it, then run the checks listed for it.

| Dependency                                      | Kept as                                                | Why, and what to do when upgrading                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ----------------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `@cloudflare/vitest-plugin`                     | `patches/@cloudflare__vitest-plugin@1.4.8.patch`       | Keeps the module snapshot it sends a reused worker under workerd's 32 MiB WebSocket message limit, past which the worker dies with `1009 Message is too large` ([cloudflare/workers-sdk#16349](https://github.com/cloudflare/workers-sdk/issues/16349)). Drop it once #16349 is fixed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `@cloudflare/computer`                          | `patches/@cloudflare__computer@0.8.0.patch`            | Adds `Workspace.remount()`, which `updateSkills` runs: computer checks a mount's version only at a Workspace's first index ([`../architecture/workspace.md`](../architecture/workspace.md) → _The Skill set_). Drop it once computer can index a mount again; rerun `apps/server/src/workspace/skills.workerd.test.ts` either way. Also update the `bash` routing lists if the Worker Shell changed ([`workers.md`](workers.md) → _The Workspace DO_).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `@cloudflare/computer`, computerd               | read for the file-change notify                        | The notify ([`../architecture/container.md`](../architecture/container.md) → _File-change notifications_) reads computer's change log, dofs' own tables (`vfs_meta`, `vfs_nodes`, `vfs_dirents`, `vfs_changes`, `_vfs_push_cursor`, `_vfs_watermark`: `apps/server/src/workspace/change-log.ts`), and the names of its sync and Workspace stub spans (`notify.ts`); and it rests on computerd answering `setxattr` on its mount as a no-op (`packages/computerd/src/fuse/driver.ts`) for which the kernel still raises `IN_ATTRIB`. When upgrading either, check the tables and span names and rerun `src/workspace/notify.workerd.test.ts` and `notify.test.ts`; check that `setxattr` still changes nothing computerd stores (no row, stat, mtime or sync change) and still reaches a watcher (by hand: computerd on a FUSE mount in Docker, `inotifywait -m -r` on it, and `cloudpid-notify` over a file); and drop the notify if computerd raises the events itself. |
| `@alchemy.run/cloudflare`                       | `patches/@alchemy.run__cloudflare@2.0.0-beta.84.patch` | Adding a Container to a Durable Object class that is already deployed: alchemy creates the class's container application before the Worker upload that Container-enables the namespace, and Cloudflare rejects it (`Durable Object namespace is not Container-enabled`); the patch retries the create until that upload lands. `alchemy` and the `@alchemy.run/*` packages share one version: keep them equal.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `isomorphic-git`                                | exact `1.44.5` in `apps/server/package.json`           | The Changes module (`apps/server/src/workspace/changes.ts`) imports it itself, since `@cloudflare/computer` does not export the copy it depends on. Rerun `src/workspace/changes.workerd.test.ts` and `changes.test.ts`, which hold the module to what real git says (`statusMatrix({ refresh: false })` must never write `.git/index`, and its reads must go through the module's file system); if its walk changed, rerun `changes.bench.workerd.test.ts` ([`../architecture/risks-and-spikes.md`](../architecture/risks-and-spikes.md)).                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `@pierre/diffs`                                 | exact version in `apps/web`                            | See [`../architecture/diffs-and-review.md`](../architecture/diffs-and-review.md) → _Rendering_, which also says why a `FileDiff` re-attached while its first highlight is pending needs `1.6.2` or later.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `effect`                                        | unstable modules opted in                              | Effect's `http` modules are unstable but allowed through `allowedUnstableApis` in `@cloudpid/config`'s shared tsconfig; add other unstable subtrees (`effect/rpc`, …) there when a change adopts them.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `@cloudflare/computer`, `pi-durable`, computerd | pinned                                                 | Previews: see [`../architecture/risks-and-spikes.md`](../architecture/risks-and-spikes.md) → _Preview packages_ and _pi-durable storage version_ before moving them.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
